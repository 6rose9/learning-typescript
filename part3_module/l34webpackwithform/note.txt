## Why `import` works here

Because your project is not running `src/index.ts` directly with Node.

### What is actually happening

- `package.json` has `"type": "commonjs"` → that only tells Node how to interpret `.js` files if you run them directly.
- Your source is `.ts` and goes through `ts-loader` + `webpack`.
- tsconfig.json uses `"module": "ES2020"`, so TypeScript treats your `import`/`export` as ES module syntax.
- Webpack bundles the result into `public/bundle.js`, so the browser gets a working bundle.

### Important distinction

- `type: "commonjs"` affects Node module resolution for `.js` files.
- It does not stop TypeScript from using `import` in `.ts` files.
- It also does not stop webpack from bundling ES-style imports.

### In short

`commonjs` in `package.json` is about Node runtime behavior.

But in your webpack project:
- TypeScript compiles `.ts`
- webpack bundles modules
- `import { greeting } from "./components/app";` is allowed and transformed

So yes, CommonJS normally uses `require`, but your build toolchain is handling `import` for you.
